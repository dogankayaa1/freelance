Laravel Fortify ve Spatie Rol Yönetimi Kurulum Rehberi

Bu proje için not: Dokümandaki örnekleri uygulamadan önce aşağıdaki mevcut durum ve dosya haritasını okuyun. HTML formu kullanıcı deneyimi sağlar; gerçek güvenlik Fortify aksiyonları, middleware ve sunucu tarafı doğrulaması ile sağlanır.

Proje Durumu ve Öncelikli Düzeltmeler

Spatie paketi kurulu ve etkin. spatie/laravel-permission ile admin ve user rolleri RolePermissionSeeder üzerinden oluşturulur. Örnek kullanıcıları eklemek için php artisan db:seed komutunu çalıştırın.
Yetkisiz erişim riski: routes/web.php içindeki /dashboard rotası şu anda auth middleware'i olmadan tanımlı. Giriş yapmayan kullanıcılar da sayfayı görebilir. Rotayı aşağıdaki gibi değiştirin:
<?php

use Illuminate\Support\Facades\Route;

Route::get('/', fn () => view('auth.login'));

Route::middleware('auth')->get('/dashboard', function () {
    return view('dashboard');
})->name('dashboard');

config/fortify.php dosyanızda şu özellikler aktif: kayıt, şifre sıfırlama, profil/sifre güncelleme, iki faktörlü doğrulama ve passkey. E-posta doğrulaması kapalıdır.

Dosya Haritası: Hangi Dosya Neden Kullanılır?

Dosya Sorumluluğu Neden önemlidir?
config/fortify.php Fortify özellikleri, route middleware'i, rate limit ve passkey origin ayarları. Özellik burada kapalıysa Blade formu tek başına çalışmaz.
app/Providers/FortifyServiceProvider.php Blade görünümlerini ve aksiyon sınıflarını Fortify'a bağlar. Giriş, 2FA ve passkey istek limitleri burada tanımlıdır.
app/Actions/Fortify/CreateNewUser.php Kayıt verisini doğrular, kullanıcıyı oluşturur. E-posta benzersizliği ve parola kuralları istemcide değil sunucuda zorlanır.
app/Actions/Fortify/UpdateUserPassword.php Mevcut parolayı kontrol eder ve yeni parolayı kaydeder. current_password:web doğrulaması hesap ele geçirilmesinin etkisini azaltır.
app/Models/User.php Kimlik doğrulama modeli. password gizlidir, hashed cast'i parolayı güvenli hash olarak saklar.
resources/views/auth/*.blade.php Kullanıcıya gösterilen form ekranları. Her veri değiştiren formda @csrf bulunmalıdır.
routes/web.php Uygulamanıza özel sayfalar. Hassas sayfalarda auth, gerekirse verified ve role gerekir.
.env APP_KEY, mail ve ortam gizlileri. Git'e eklenmez; üretimde APP_DEBUG=false olmalıdır.

1 Kurulum Paketleri

Fortify ve Spatie paketlerini projenize dahil edin ve yapılandırma dosyalarını yayınlayın.

# 1. Fortify Paketini Yükleyin ve Kurun
composer require laravel/fortify
php artisan fortify:install
php artisan migrate

# 2. Spatie Rol & İzin Paketini Yükleyin
composer require spatie/laravel-permission
php artisan vendor:publish --provider="Spatie\Permission\PermissionServiceProvider"
php artisan migrate

2 FortifyServiceProvider Yapılandırması

Görünümleri (View) tanımlamak için app/Providers/FortifyServiceProvider.php dosyanızı güncelleyin.

<?php

namespace App\Providers;

use Illuminate\Support\ServiceProvider;
use Laravel\Fortify\Fortify;

class FortifyServiceProvider extends ServiceProvider
{
    public function boot(): void
    {
        // 1. Giriş Sayfası
        Fortify::loginView(function () {
            return view('auth.login');
        });

        // 2. Kayıt Sayfası
        Fortify::registerView(function () {
            return view('auth.register');
        });

        // 3. Şifremi Unuttum Sayfası
        Fortify::requestPasswordResetLinkView(function () {
            return view('auth.forgot-password');
        });

        // 4. Şifre Yenileme Formu
        Fortify::resetPasswordView(function ($request) {
            return view('auth.reset-password', ['request' => $request]);
        });
    }
}

4 İlk Kullanıcıyı Oluşturma (Tinker)

Üretimde sabit parola kullanmayın. 12345678, password veya dokümanda görünen başka bir parolayı admin hesabına atamak hesap ele geçirilmesine yol açar. Bu örnek yalnızca yerel geliştirme içindir.

Yerel ortamda rastgele, tek kullanımlık bir parola ile admin oluşturmak için:

php artisan tinker

use App\Models\User;
use Illuminate\Support\Facades\Hash;
use Illuminate\Support\Str;

$temporaryPassword = Str::password(24);
$admin = User::updateOrCreate(['email' => 'admin@example.test'], [
    'name' => 'Local Admin',
    'password' => Hash::make($temporaryPassword),
]);
$admin->syncRoles(['admin']);

dump(['email' => $admin->email, 'temporary_password' => $temporaryPassword]);
exit

Parolayı yalnızca güvenli bir parola yöneticisine kaydedin. Üretimde admin hesabını ekip onaylı bir süreç ve gizli ortam değişkenleriyle oluşturun; terminal çıktısını veya parolayı loglara, Git'e ve destek kayıtlarına koymayın.

5 Rol ve Yetki Altyapısı (Spatie)

A. Model Güncellemesi

app/Models/User.php dosyanıza HasRoles trait'ini ekleyin:

use Spatie\Permission\Traits\HasRoles;

class User extends Authenticatable
{
    use HasRoles;
    // ...
}
B. Rol Oluşturma ve Atama (Seeder Örneği)

Bu projede database/seeders/RolePermissionSeeder.php rolleri, izni ve iki test kullanıcısını tekrar çalıştırılabilir şekilde oluşturur:

use App\Models\User;
use Illuminate\Support\Facades\Hash;
use Spatie\Permission\Models\Permission;
use Spatie\Permission\Models\Role;

$permission = Permission::firstOrCreate([
    'name' => 'admin.dashboard.view',
    'guard_name' => 'web',
]);
$adminRole = Role::firstOrCreate(['name' => 'admin', 'guard_name' => 'web']);
$userRole = Role::firstOrCreate(['name' => 'user', 'guard_name' => 'web']);
$adminRole->syncPermissions([$permission]);

$admin = User::updateOrCreate(['email' => 'admin@example.test'], [
    'name' => 'Test Admin',
    'password' => Hash::make('password'),
]);
$admin->syncRoles([$adminRole]);

// Bu örnek kullanıcılar yalnızca local/testing ortamında oluşturulmalıdır.
// Üretimde seeder sadece rol ve izinleri oluşturmalı; tahmin edilebilir parola eklememelidir.
// Kullanıcıları ve rolleri yerelde eklemek/güncellemek için:
// php artisan db:seed
C. Route / Middleware Kontrolü
// bootstrap/app.php: role middleware alias'ını kaydedin
$middleware->alias([
    'role' => \Spatie\Permission\Middleware\RoleMiddleware::class,
]);

// routes/web.php: sadece admin rolüne erişim verin
Route::middleware(['auth', 'role:admin'])
    ->view('/admin', 'admin.dashboard')
    ->name('admin.dashboard');
D. Giriş Yapan Kullanıcının Rol ve İzinlerini Blade'de Gösterme

HasRoles trait'i eklendikten sonra oturum açan kullanıcıya auth()->user() ile ulaşabilirsiniz. getRoleNames() kullanıcının rollerini, getAllPermissions() ise doğrudan ve rol üzerinden gelen tüm izinlerini verir. 

<!-- resources/views/dashboard.blade.php -->
<section class="border rounded p-3">
    <h2 class="h5">Yetkileriniz</h2>

    <p><strong>Roller:</strong></p>
    @forelse (auth()->user()->getRoleNames() as $role)
        <span class="badge text-bg-primary">{{ $role }}</span>
    @empty
        <span class="text-muted">Atanmış rol yok.</span>
    @endforelse

    <p class="mt-3"><strong>İzinler:</strong></p>
    <ul>
        @forelse (auth()->user()->getAllPermissions() as $permission)
            <li>{{ $permission->name }}</li>
        @empty
            <li class="text-muted">Atanmış izin yok.</li>
        @endforelse
    </ul>
</section>

Belirli bir rol veya izne göre arayüz elemanı göstermek için Spatie Blade direktiflerini kullanın:

@role('admin')
    <a href="{{ route('admin.dashboard') }}">Yönetim paneli</a>
@endrole

@can('admin.dashboard.view')
    <span>Yönetim paneli izniniz var.</span>
@endcan
Önemli: Blade direktifleri yalnızca arayüzde görünürlüğü değiştirir. Gerçek yetkilendirme için route veya controller üzerinde auth, role:admin ya da permission:... middleware'i kullanmaya devam edin.

8 İki Faktörlü Doğrulama (2FA) ve Passkey

Bu iki özellik projede zaten aktiftir. 2FA, authenticator uygulamasındaki kodu; passkey ise cihazın PIN'i veya biyometrisini kullanır. İkisi de yalnızca şifreye göre daha güçlü bir koruma sağlar.

A. 2FA Açma, Onaylama ve Kapatma

config/fortify.php içindeki confirm ve confirmPassword ayarları sayesinde kullanıcı, hassas 2FA bilgilerini görmeden önce parolasını yeniden onaylamalıdır.

C. Passkey

Passkey HTML ile tek başına oluşturulamaz. Tarayıcıda WebAuthn API'si kullanılır. APP_URL, relying_party_id ve allowed_origins tam olarak aynı güvenli alanı işaret etmelidir; HTTPS zorunludur. 

<!-- resources/views/security/passkeys.blade.php -->
<button type="button" id="add-passkey" class="btn btn-dark">
    Bu cihazda passkey oluştur
</button>

<script>
document.querySelector('#add-passkey').addEventListener('click', async () => {
    // GET /user/passkeys/options ile sunucudan challenge/options alın.
    // navigator.credentials.create({ publicKey: options }) ile credential oluşturun.
    // Sonucu CSRF korumalı POST /user/passkeys isteğiyle gönderin.
});
</script>
Bu projede passkey rotalarını Laravel\Passkeys sağlar: kayıt seçenekleri için GET /user/passkeys/options, kayıt için POST /user/passkeys ve silmek için DELETE /user/passkeys/{passkey}. Payload formatını tahmin etmeyin; WebAuthn binary alanları doğru encode edilmelidir.

9 E-posta Doğrulama

Bu projede e-posta doğrulama kapalıdır. Yönetim, ödeme veya kişisel veri sayfaları için açılması önerilir. Önce config/fortify.php içindeki Features::emailVerification() satırının yorumunu kaldırın; sonra modeli güncelleyin. 

// app/Models/User.php
use Illuminate\Contracts\Auth\MustVerifyEmail;

class User extends Authenticatable implements MustVerifyEmail
{
    // Mevcut HasFactory ve Notifiable trait'leri burada kalır.
}

Doğrulama e-postasını tekrar gönderen HTML formu:

<form method="POST" action="{{ route('verification.send') }}">

Route::middleware(['auth', 'verified'])->get('/account', function () {
    return view('account');

10 Rota Güvenliği ve Rol Kontrolü

Rota tanımlarında rollere göre erişim kısıtlaması uygulamak için middleware'ler ve middleware grupları kullanılır. İşte sıkça kullanılan rota güvenliği yapıları:

A. Tek Bir Role İzin Verme (Örn: Sadece admin)
Route::middleware(['auth', 'role:admin'])->group(function () {
    Route::get('/ayarlar', [SettingController::class, 'index'])->name('admin');
    Route::post('/ayarlar', [SettingController::class, 'update'])->name('admin.update');
});
B. Birden Fazla Role İzin Verme (Veya Mantığı - Örn: admin VEYA editor)

Admin VEYA Editor olan herkes bu gruba girebilir:

Route::middleware(['auth', 'role:admin|editor'])->group(function () {
    Route::get('/ayarlar', [SettingController::class, 'index'])->name('admin');
    Route::post('/ayarlar', [SettingController::class, 'update'])->name('admin.update');
});

Virgül ile de yazılabilir (kullandığınız custom middleware yapısına göre değişebilir):

Route::middleware(['auth', 'role:admin,editor,manager'])->group(function () {
    // ...
});
C. Birden Fazla Rolü Zorunlu Kılma (Ve Mantığı - Örn: Hem admin HEM super-admin)

Kullanıcı hem 'admin' OLMALI hem de 'super-admin' OLMALI:

Route::middleware(['auth', 'role:admin', 'role:super-admin'])->group(function () {
    Route::get('/hassas-ayarlar', [SettingController::class, 'index']);
});

11 Güvenli CRUD İşlemleri

Laravel'de CRUD işlemlerinin güvenli bir şekilde yapılması için doğrulama (validation), kütlesel atama koruması (mass assignment) ve yetkilendirme (authorization) adımları uygulanmalıdır.

A. Model Tanımlaması (Kütlesel Atama Koruması)

Kötü niyetli kullanıcıların veritabanındaki is_admin gibi yetki alanlarını değiştirmesini engellemek için $fillable tanımı kullanılmalıdır.

<?php

namespace App\Models;

use Illuminate\Database\Eloquent\Model;
use Illuminate\Database\Eloquent\Factories\HasFactory;

class Post extends Model
{
    use HasFactory;

    // Sadece bu alanların dışarıdan kütlesel olarak doldurulmasına izin verilir.
    protected $fillable = [
        'title',
        'content',
        'is_published',
    ];
}
B. Form Request ile Güvenli Giriş Doğrulama

İstek verilerini Controller içinde doğrulamak yerine Form Request sınıfları kullanmak kodu temiz tutar ve güvenliği merkezileştirir.

<?php

namespace App\Http\Requests;

use Illuminate\Foundation\Http\FormRequest;

class StorePostRequest extends FormRequest
{
    public function authorize(): bool
    {
        // Kullanıcının bu isteği göndermeye yetkisi olup olmadığı
        return auth()->check();
    }

    public function rules(): array
    {
        return [
            'title' => 'required|string|min:5|max:255',
            'content' => 'required|string|min:10',
            'is_published' => 'boolean',
        ];
    }
}
C. Güvenli Controller CRUD Metotları
<?php

namespace App\Http\Controllers;

use App\Models\Post;
use App\Http\Requests\StorePostRequest;
use Illuminate\Http\Request;

class PostController extends Controller
{
    // 1. READ (Listeleme - SQL Injection Korumalı)
    public function index()
    {
        $posts = Post::where('is_published', true)
                     ->orderBy('created_at', 'desc')
                     ->paginate(10);

        return view('posts.index', compact('posts'));
    }

    // 2. CREATE (Kayıt Formu Gösterimi)
    public function create()
    {
        return view('posts.create');
    }

    // 3. STORE (Veri Kaydetme - Güvenli Kütlesel Atama)
    public function store(StorePostRequest $request)
    {
        // Sadece doğrulanmış verileri alıyoruz
        $validated = $request->validated();

        // Kullanıcı ID'sini sunucu tarafında güvenle atıyoruz
        $validated['user_id'] = auth()->id();

        Post::create($validated);

        return redirect()->route('posts.index')->with('success', 'İçerik başarıyla oluşturuldu.');
    }

    // 4. READ (Detay Gösterimi - XSS Korumalı)
    public function show(Post $post)
    {
        return view('posts.show', compact('post'));
    }

    // 5. UPDATE (Düzenleme Formu Gösterimi - Yetki Kontrolü)
    public function edit(Post $post)
    {
        $this->authorize('update', $post); // Policy üzerinden kontrol

        return view('posts.edit', compact('post'));
    }

    // 6. UPDATE (Veri Güncelleme - Güvenli Güncelleme)
    public function update(StorePostRequest $request, Post $post)
    {
        $this->authorize('update', $post);

        $post->update($request->validated());

        return redirect()->route('posts.show', $post)->with('success', 'İçerik güncellendi.');
    }

    // 7. DELETE (Veri Silme - Güvenli Silme)
    public function destroy(Post $post)
    {
        $this->authorize('delete', $post);

        $post->delete();

        return redirect()->route('posts.index')->with('success', 'İçerik silindi.');
    }
}

use Illuminate\Http\Request;

class CategoryController extends Controller
{
    // 1. Kategorileri Listeleme (Read)
    public function index()
    {
        $categories = Category::latest()->get();
        return view('categories.index', compact('categories'));
    }

    // 2. Yeni Kategori Ekleme Formu (Create View)
    public function create()
    {
        return view('categories.create');
    }

    // 3. Yeni Kategori Kaydetme (Store)
    public function store(Request $request)
    {
        $request->validate([
            'name' => 'required|string|max:255',
        ]);

        Category::create([
            'name' => $request->name
        ]);

        return redirect()->route('categories.index')->with('success', 'Kategori başarıyla eklendi!');
    }

    // 4. Kategori Düzenleme Formu (Edit View)
    public function edit($id)
    {
        $category = Category::findOrFail($id);
        return view('categories.edit', compact('category'));
    }

    // 5. Kategori Güncelleme (Update)
    public function update(Request $request, $id)
    {
        $request->validate([
            'name' => 'required|string|max:255',
        ]);

        $category = Category::findOrFail($id);
        $category->update([
            'name' => $request->name
        ]);

        return redirect()->route('categories.index')->with('success', 'Kategori başarıyla güncellendi!');
    }

    // 6. Kategori Silme (Destroy)
    public function destroy($id)
    {
        $category = Category::findOrFail($id);
        $category->delete();

        return redirect()->route('categories.index')->with('success', 'Kategori başarıyla silindi!');
    }
}

15 Migration Veri Tipleri, Sütun Özellikleri ve Validasyon Karşılıkları

Laravel'de veritabanı şeması oluştururken kullanılan veri tipleri, bunların aldığı parametreler ve formdan gelen isteklerde (Request Validation) nasıl doğrulanması gerektiği aşağıda listelenmiştir.

1. Metin ve Karakter (String / Text)
Migration Kod Örneği Açıklama Form Validasyon Karşılığı (Controller)
$table->string('baslik', 150); Kısa metinler. (Varsayılan 255 karakterdir). 'baslik' => 'required|string|max:150'
$table->char('kod', 5); Sabit uzunluklu karakter dizileri. 'kod' => 'required|string|size:5'
$table->text('icerik'); Uzun metinler (makale, açıklama vb.). 'icerik' => 'required|string|min:10'
$table->mediumText('detay'); Orta uzunluktaki metinler (~16MB). 'detay' => 'nullable|string'
$table->longText('aciklama'); Çok büyük metin alanları (~4GB). 'aciklama' => 'nullable|string'
$table->json('ayarlar'); JSON verisi depolamak için kullanılır. 'ayarlar' => 'required|json' veya 'array'
2. Sayısal (Numeric)
Migration Kod Örneği Açıklama Form Validasyon Karşılığı (Controller)
$table->integer('yas'); Standart tam sayılar. 'yas' => 'required|integer|min:0|max:120'
$table->tinyInteger('durum'); Küçük tam sayılar (0-255 / enayi tipler). 'durum' => 'required|integer|between:0,255'
$table->bigInteger('telefon'); Çok büyük tam sayılar (ID, Telefon vb.). 'telefon' => 'required|numeric'
$table->float('oran'); Kayan noktalı (ondalıklı) sayılar. 'oran' => 'required|numeric'
$table->decimal('fiyat', 8, 2); Hassas finansal sayılar (8 basamak, 2 virgülden sonra). 'fiyat' => 'required|numeric|between:0,999999.99'
$table->boolean('aktif'); True/False (1 veya 0) değerleri. 'aktif' => 'nullable|boolean'
3. Tarih ve Zaman (Date / Time)
Migration Kod Örneği Açıklama Form Validasyon Karşılığı (Controller)
$table->date('dogum_tarihi'); Sadece tarih tutar (YYYY-MM-DD). 'dogum_tarihi' => 'required|date'
$table->time('mesai_baslangici'); Sadece saat tutar (HH:MM:SS). 'mesai_baslangici' => 'required|date_format:H:i'
$table->dateTime('giris_zamani'); Tarih ve zamanı birlikte tutar. 'giris_zamani' => 'required|date'
$table->timestamp('kayit_zamani'); UNIX zaman damgası türünde zaman. 'kayit_zamani' => 'required|date'
$table->timestamps(); created_at ve updated_at ekler. Formdan doğrudan gelmez (Otomatik).
4. Tanımlayıcılar (ID ve Foreign Key)
Migration Kod Örneği Açıklama Form Validasyon Karşılığı (Controller)
$table->id(); Otomatik artan birincil anahtar (Primary Key). Formdan gelmez (Veritabanı üretir).
$table->foreignId('kategori_id'); İlişkili tablodaki yabancı anahtar. 'kategori_id' => 'required|exists:categories,id'
5. Sık Kullanılan Sütun Değiştiriciler (Modifiers)

Sütun türlerinin sonuna zincirleme fonksiyon olarak eklenerek sütun davranışı özelleştirilir:

->nullable()

Sütunun boş (NULL) bırakılmasına izin verir. Validasyonda karşılığı nullable kuralıdır.

->default('deger')

Formdan veri gelmediğinde veritabanının otomatik yazacağı varsayılan değeri belirler.

->unique()

Sütundaki verilerin benzersiz olmasını sağlar. Validasyonda karşılığı unique:tablo_adi,sutun_adi kuralıdır.

->unsigned()

Sayısal değerin negatif olmamasını sağlar (0 ve pozitif). Validasyonda karşılığı min:0 kuralıdır.

Migration & Validasyon Bütünleşik Örneği

Aşağıda örnek bir Ürün (Product) tablosu migration dosyası ve Controller tarafındaki validasyon kuralı gösterilmiştir:

1. Migration Yapılandırması (database/migrations/xxxx_create_products_table.php)

Schema::create('products', function (Blueprint $table) {
    $table->id();
    $table->foreignId('category_id')->constrained(); // categories tablosuna bağlanır
    $table->string('urun_kodu', 50)->unique();
    $table->string('baslik', 150);
    $table->text('aciklama')->nullable();
    $table->decimal('fiyat', 8, 2);
    $table->integer('stok')->default(0)->unsigned();
    $table->boolean('aktif')->default(true);
    $table->timestamps();
});

2. Controller Validasyon Yapılandırması (ProductController.php)

$request->validate([
    'category_id' => 'required|exists:categories,id',
    'urun_kodu'   => 'required|string|max:50|unique:products,urun_kodu',
    'baslik'      => 'required|string|max:150',
    'aciklama'    => 'nullable|string',

16 Laravel Pagination (Sayfalandırma) Yapılandırması

Veritabanından büyük miktarda veri çekerken performans ve kullanıcı deneyimi için veriler tek seferde değil, sayfa sayfa (paginate) çekilmelidir. Laravel'de Bootstrap uyumlu sayfalandırma 3 adımda yapılandırılır.

A. AppServiceProvider Yapılandırması

Laravel varsayılan olarak Tailwind CSS pagination şablonunu kullanır. Bootstrap 5 tasarım şablonunu aktifleştirmek için app/Providers/AppServiceProvider.php içindeki boot() metoduna ekleme yapılır:

<?php

namespace App\Providers;

use Illuminate\Pagination\Paginator;
use Illuminate\Support\ServiceProvider;

class AppServiceProvider extends ServiceProvider
{
    /**
     * Register any application services.
     */
    public function register(): void
    {
        //
    }

    /**
     * Bootstrap any application services.
     */
    public function boot(): void
    {
        // Sayfalandırma şablonunu Bootstrap 5 olarak ayarlıyoruz
        Paginator::useBootstrapFive();
    }
}
B. Controller İçinde Sayfalandırma (UrunController.php)

Veritabanı sorgusunda tüm veriyi çeken all() veya get() yerine paginate(sayi) metodu kullanılır:

<?php

namespace App\Http\Controllers;

use App\Models\Category;
use App\Models\Urun;
use Illuminate\Http\Request;

class UrunController extends Controller
{
    public function index()
    {
        $categories = Category::latest()->get();

        // Her sayfada 2 veri gösterilecek şekilde veriyi çekiyoruz
        $getir = Urun::paginate(2);

        return view('urun', compact('categories', 'getir'));
    }
}
C. Blade Arayüzünde Türkçe ve Özelleştirilmiş Pagination Gösterimi

Blade üzerinde toplam kayıt sayısını Türkçe metinle göstermek ve Bootstrap pagination butonlarını sağa yaslayarak küçük boyutta göstermek için aşağıdaki kod yapısı kullanılır:

<!-- Pagination Arayüzü -->
<div class="d-flex justify-content-between align-items-center mt-4 w-100">
    <!-- Sol taraftaki dinamik Türkçe bilgi alanı -->
    <span class="text-muted small">
        Toplam {{ $getir->total() }} kayıttan {{ $getir->firstItem() }}-{{ $getir->lastItem() }} arası gösteriliyor
    </span>

    <!-- Sağ taraftaki küçük boyutlu pagination butonları -->
    <div class="pagination-sm">
        {{ $getir->links('pagination::bootstrap-4') }}
    </div>
</div>
İpucu: Sayfalandırılmış nesne üzerinde kullanabileceğin yararlı metotlar:
  • $getir->total(): Toplam toplam kayıt sayısını döner.
  • $getir->firstItem(): Mevcut sayfadaki ilk kaydın sıra numarasını verir.
  • $getir->lastItem(): Mevcut sayfadaki son kaydın sıra numarasını verir.
  • $getir->links(): Sayfa geçiş butonlarının HTML kodunu üretir.

17 Resource Rotaları (Tek Satırda 7 CRUD Rotası)

Laravel'in Route::resource yapısı, standart CRUD işlemlerine ait tüm HTTP metotlarını ve rota isimlerini arka planda otomatik olarak ilgili Controller metotlarına bağlar.

Önerilen Yöntem: Her bir rotayı tek tek Route::get, Route::post yazarak tanımlamak yerine tek bir Route::resource satırı kullanmak dosya kalabalığını önler ve standart bir mimari sağlar.
A. Rota Dosyası Tanımlaması (routes/web.php)
<?php

use Illuminate\Support\Facades\Route;
use App\Http\Controllers\TedarikcilerController;

// Bu tek satır kod arka planda 7 standart rotayı otomatik oluşturur:
Route::resource('tedarikciler', TedarikcilerController::class);
B. Otomatik Oluşturulan Rota Haritası
URL / Adres HTTP Metodu Controller Metodu Rota İsmi (Route Name) Ne İşe Yarar?
/tedarikciler GET index() tedarikciler.index Tüm tedarikçileri listeler.
/tedarikciler/create GET create() tedarikciler.create Yeni tedarikçi ekleme formunu açar.
/tedarikciler POST store() tedarikciler.store Formdan gelen yeni tedarikçiyi kaydeder.
/tedarikciler/{tedarikciler} GET show() tedarikciler.show Tek bir tedarikçinin detayını gösterir.
/tedarikciler/{tedarikciler}/edit GET edit() tedarikciler.edit Tedarikçi düzenleme formunu açar.
/tedarikciler/{tedarikciler} PUT / PATCH update() tedarikciler.update Düzenlenen tedarikçiyi günceller.
/tedarikciler/{tedarikciler} DELETE destroy() tedarikciler.destroy Tedarikçiyi veritabanından siler.
C. Controller Metot Açıklamaları ve Yapısı (TedarikcilerController.php)

Resource rotalarının Controller tarafındaki karşılıkları ve her bir metodun üstlendiği görev aşağıda detaylandırılmıştır:

<?php

namespace App\Http\Controllers;

use App\Models\Tedarikci;
use Illuminate\Http\Request;

class TedarikcilerController extends Controller
{
    /**
     * LİSTELEME SAYFASI (GET)
     * URL: /tedarikciler
     * Rota İsmi: tedarikciler.index
     * Görevi: Veritabanındaki tüm kayıtları çeker ve listeleme ekranına (view) gönderir.
     */
    public function index()
    {
        $tedarikciler = Tedarikci::latest()->get();
        return view('tedarikciler.index', compact('tedarikciler'));
    }

    /**
     * YENİ EKLEME FORMU (GET)
     * URL: /tedarikciler/create
     * Rota İsmi: tedarikciler.create
     * Görevi: Kullanıcının yeni veri gireceği BOŞ HTML form sayfasını ekrana getirir.
     * NOT: Veritabanına herhangi bir kayıt YAPMAZ.
     */
    public function create()
    {
        return view('tedarikciler.create');
    }

    /**
     * VERİ KAYDETME İŞLEMİ (POST)
     * URL: /tedarikciler
     * Rota İsmi: tedarikciler.store
     * Görevi: create() sayfasındaki formdan POST ile gelen verileri ($request) yakalar,
     * doğrulama (validation) yapar ve veritabanına yeni kayıt olarak ekler.
     */
    public function store(Request $request)
    {
        $request->validate([
            'unvan' => 'required|string|max:255',
        ]);

        Tedarikci::create($request->all());

        return redirect()->route('tedarikciler.index')->with('success', 'Tedarikçi eklendi!');
    }

    /**
     * TEKİL DETAY SAYFASI (GET)
     * URL: /tedarikciler/{id}
     * Rota İsmi: tedarikciler.show
     * Görevi: ID parametresine göre ilgili kaydı bulur ve detay ekranında gösterir.
     */
    public function show($id)
    {
        $tedarikci = Tedarikci::findOrFail($id);
        return view('tedarikciler.show', compact('tedarikci'));
    }

    /**
     * GÜNCELLEME FORMU (GET)
     * URL: /tedarikciler/{id}/edit
     * Rota İsmi: tedarikciler.edit
     * Görevi: Güncellenmek istenen veriyi ID ile veritabanından çeker ve
     * DOLU HTML form sayfasını ekrana getirir.
     * NOT: Veritabanında güncelleme YAPMAZ, sadece mevcut veriyi forma basar.
     */
    public function edit($id)
    {
        $tedarikci = Tedarikci::findOrFail($id);
        return view('tedarikciler.edit', compact('tedarikci'));
    }

    /**
     * VERİ GÜNCELLEME İŞLEMİ (PUT/PATCH)
     * URL: /tedarikciler/{id}
     * Rota İsmi: tedarikciler.update
     * Görevi: edit() sayfasındaki formdan PUT isteği ile gelen yeni verileri yakalar,
     * doğrulama yapar ve ilgili kaydı veritabanında günceller.
     */
    public function update(Request $request, $id)
    {
        $request->validate([
            'unvan' => 'required|string|max:255',
        ]);

        $tedarikci = Tedarikci::findOrFail($id);
        $tedarikci->update($request->all());

        return redirect()->route('tedarikciler.index')->with('success', 'Tedarikçi güncellendi!');
    }

    /**
     * SILME İŞLEMİ (DELETE)
     * URL: /tedarikciler/{id}
     * Rota İsmi: tedarikciler.destroy
     * Görevi: Gönderilen ID parametresine ait kaydı veritabanından tamamen siler.
     */
    public function destroy($id)
    {
        $tedarikci = Tedarikci::findOrFail($id);
        $tedarikci->delete();

        return redirect()->route('tedarikciler.index')->with('success', 'Tedarikçi silindi!');
    }
}
D. Blade Formlarında Resource Rotalarının Kullanımı

Resource rotaları otomatik isimler aldığı için Blade dosyalarında `route()` yardımcısı şu şekilde kullanılır:

1. Ekleme Formu (resources/views/tedarikciler/create.blade.php)

<form action="{{ route('tedarikciler.store') }}" method="POST">
    @csrf

    <div class="mb-3">
        <label for="unvan" class="form-label">Tedarikçi Ünvanı</label>
        <input type="text" id="unvan" name="unvan" value="{{ old('unvan') }}" class="form-control">
    </div>

    <button type="submit" class="btn btn-primary">Kaydet</button>
</form>

2. Güncelleme Formu (resources/views/tedarikciler/edit.blade.php)

<!-- Güncelleme formunda action parametresi olarak nesnenin ID'si verilir -->
<form action="{{ route('tedarikciler.update', $tedarikci->id) }}" method="POST">
    @csrf
    <!-- HTTP PUT Metot Maskeleme -->
    @method('PUT')

    <div class="mb-3">
        <label for="unvan" class="form-label">Tedarikçi Ünvanı</label>
        <input type="text" id="unvan" name="unvan" value="{{ old('unvan', $tedarikci->unvan) }}" class="form-control">
    </div>

    <button type="submit" class="btn btn-success">Güncelle</button>
</form>

3. Silme Formu (resources/views/tedarikciler/index.blade.php)

<form action="{{ route('tedarikciler.destroy', $tedarikci->id) }}" method="POST" class="d-inline">
    @csrf
    @method('DELETE')

E. Resource Rotalarını Sınırlandırma (only & except)

Varsayılan olarak açılan 7 rotanın hepsine ihtiyacınız yoksa, güvenlik veya mimari nedenlerle sadece belirlediğiniz metotların çalışmasını sağlayabilirsiniz.

1. Sadece Belirli Rotaları Açmak (only)

Aşağıdaki tanım sadece index, show ve destroy rotalarını oluşturur; form ekranları (create, edit) veya kayıt metotları (store, update) pasif kalır.

Route::resource('tedarikciler', TedarikcilerController::class)->only([
    'index', 'show', 'destroy'
]);

2. Belirli Rotaları Hariç Tutmak (except)

Aşağıdaki tanım destroy (silme) hariç geri kalan 6 rotanın tamamını oluşturur.

Route::resource('tedarikciler', TedarikcilerController::class)->except([
    'destroy'
]);
Neden Kullanılır? Örneğin dışarıya açık bir ilan listesinde ziyaretçilerin veri eklemesini/silmesini engellemek için sadece only(['index', 'show']) tanımlayarak arka planda gereksiz URL ve güvenlik açıklarının oluşmasını doğrudan engellemiş olursunuz.
İpucu (Terminal Komutu): Tüm bu metotları içinde hazır barındıran bir Controller sınıfı üretmek için terminalde --resource bayrağını kullanabilirsin: 
php artisan make:controller TedarikcilerController --resource

Üretim Güvenlik Kontrol Listesi

  • HTTPS: APP_URL=https://... ve SESSION_SECURE_COOKIE=true kullanın. HTTPS olmadan passkey güvenilir değildir.
  • Gizliler: .env, APP_KEY, SMTP parolası ve token'lar Git'e eklenmez. .env.example sadece sahte değer içerir.
  • Hata sayfası: üretimde APP_DEBUG=false olmalıdır. Stack trace ve ortam bilgisi kullanıcıya görünmemelidir.
  • CSRF: her POST/PUT/PATCH/DELETE Blade formunda @csrf kullanın. Çıkış, silme ve ayar değiştirme işlemlerini GET ile yapmayın.
  • Yetkilendirme: hassas rotalarda auth, gerektiğinde verified, password.confirm ve role middleware'i kullanın.
  • Parola: app/Actions/Fortify/PasswordValidationRules.php kurallarını inceleyin. Parolayı asla loglamayın ve düz metin olarak saklamayın.
  • Rate limit: FortifyServiceProvider.php içindeki login/2FA/passkey limitlerini kaldırmayın. Login limiti e-posta + IP bazlıdır.
  • XSS: Blade'de {{ $value }} kullanın. Güvenilmeyen veriyi {!! !!} ile yazdırmak XSS riski oluşturur.
  • Güncelleme: düzenli olarak composer audit çalıştırın; PHP, Laravel ve Fortify güvenlik yamalarını uygulayın.
  • Yedek: veritabanı yedeklerini şifreleyin, erişimi sınırlandırın ve geri yükleme testleri yapın.
